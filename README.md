# 支线 · Android 0.1.0 文字体验版

Flutter 一套业务与界面代码，首轮交付 Android 调试 APK；保留 iOS 工程，未进行 iOS 编译或真机验证。这个版本用来验证“日常轻量任务 → 记录发现 → 私密探索册”是否值得继续做。

## 已可体验

- 8 类必选身份；6 项可选探索偏好，最多选 3 项，之后可修改。
- 浏览任务无需登录；选择领取时使用昵称 + 密码注册或登录，不收集手机号。昵称是登录名，内部另有稳定随机账号 ID。
- 16 条审核过的低难度任务，约 5–10 分钟，均有室内／原地替代，不强迫社交、消费或高强度活动。
- 每天推荐一个，完成后主动选择下一条；每天换题一次，不做连续打卡、不设惩罚。停止任务不消耗额外次数，仍可随时停止。
- 最多 300 Unicode 码点的文字记录、手动保存草稿、返回时尝试保存、私密探索册、单条删除。
- 主动确认后生成图片分享卡；不包含账号昵称、身份和偏好；JSON 导出；验证密码后删除账号。
- 本机持久化与可选远程 API 两种实现。远程使用 Node 24 + SQLite，昵称唯一由数据库约束，按账号隔离记录。

## 当前交付边界

交付 APK 没有配置公网 API，默认单机体验：昵称仅在当前安装中唯一；没有跨手机同步，卸载或清除数据会丢失账号和记录。账号密码采用随机盐 PBKDF2；记录正文尚未额外加密。调试包不适合保存真实敏感资料，建议使用独立测试密码。

后端源码已实现并经过真实客户端联调，但**没有部署到公网，也没有建立 GitHub 远程仓库**。给 APK 配置 API 地址需要先部署服务，再重新构建；不是在界面中切换。单机记录暂不支持迁移至云端。

身份目前用于部分任务的场景提示，探索偏好可保存和修改；任务仍以固定目录顺序分配，**尚无按偏好排序或 AI 推荐**。本机按设备自然日重置换题机会，远程按 Asia/Shanghai 自然日；本机改时钟可以影响计数，不视为防作弊系统。

图片、录音、视频、定时提醒、密码找回暂未启用。媒体按钮禁用，界面中仅展示后续限制；没有上传或元数据清理保障的虚假承诺。媒体计划：图片 ≤3 张且每张 ≤10 MB；录音 1 段 ≤60 秒且 ≤10 MB；视频 1 段 ≤30 秒且 ≤50 MB。格式、解码、内容和隐私处理需后续在客户端／服务端共同落实。

没有公共广场、用户互动、定位、广告或行为统计。尚未完成适龄政策、公开服务条款和正式隐私政策，不能作为已完成合规审查的公开产品。

## 验证结果

- Flutter analyze：无问题。
- Flutter test：21 项通过，包括身份与登录流程、320 像素窄屏、任务次数、持久化、会话失效处理，以及真实 Flutter → Node API 合约测试。
- Node 后端集成测试：10 项通过，包括并发昵称唯一／换题、账号隔离、删除、会话与输入边界。
- Android 三架构 APK 构建成功；最终 ARM64 / ARMv7 安装包通过 APK v2 签名校验；最低 Android 7.0。
- 已用 Flutter Web 开发预览检查实际布局；screenshots 不是安卓真机截图。未连接 Android 真机，安装、键盘、系统分享和导出面板仍需手机验收。

## 开发与构建

参见 [BUILDING.md](BUILDING.md)。Flutter 3.47.0 / Dart 3.13.0 / Java 21；后端和真实合约测试需要 Node 24。

```text
flutter pub get
flutter analyze
flutter test
node --test server/server.test.mjs
flutter build apk --debug --split-per-abi
```

GitHub Actions 的手动构建文件在 `.github/workflows/android-alpha.yml`，尚未在 GitHub 执行。工作流不自动公开源码或发布 Release。

后端启动、HTTPS 部署和数据边界见 [server/README.md](server/README.md)。线上服务需要自行选定服务器／托管平台和域名，确认备份与删除策略；禁止把数据库、密码或令牌提交到仓库。

## 第一轮建议验证

1. 安装 APK，选身份并跳过或选择偏好，浏览今日任务。
2. 选择支线，创建测试昵称和密码；退出再登录，验证昵称冲突和密码错误提示。
3. 写一段内容、存草稿、退出重进，完成后检查探索册。
4. 尝试再领、换题一次、再换题受限；不合适时可以停止。
5. 在系统分享面板检查分享卡、导出文件，再验证删除记录／账号。

重点观察：任务是否让人愿意实际做、记录步骤是否太麻烦、第二天是否愿意再打开。不要为了完成次数而勉强自己。
