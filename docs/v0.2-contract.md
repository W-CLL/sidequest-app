# v0.2 implementation contract

This document coordinates the implementation; runtime data never belongs in Git.

## Ownership

- Root: domain models, catalog, dependencies/platform config, integration, documentation and delivery.
- Backend agent: server/** excluding catalog.mjs and catalog.json, server tests and backup tool.
- Repository agent: lib/repository.dart, lib/offline_store.dart, lib/sync_worker.dart, repository/contract tests.
- UI agent: lib/main.dart, lib/pages.dart, lib/media_widgets.dart, lib/media_capture.dart, UI tests/fixtures.

## Wire protocol 2

Every API request except health carries X-Sidequest-Protocol: 2. Health returns protocolVersion: 2. Ordinary JSON bodies remain limited to 16 KiB; sync batches max 10 commands. Authentication remains Bearer, never in URLs. Keep existing nickname/password auth and online preferences/replace/delete-account/logout routes.

State fields: profile, activeQuestId, recommendedQuestId, replacedOn, draft, draftAttachments (Media[]), day, canRequestNext, progressRevision (integer), recommendationHistory (last 40 IDs), entryCount. No full journal in state. GET /api/entries?q=&cursor=&limit=20 returns {entries,nextCursor,total}; stable createdAt/id ordering. GET /api/entries/:id returns {entry}.

Entry fields: id (= clientRecordId), questId, questTitle, text (1–500 code points), createdAt (captured time), updatedAt, revision, attachments (Media[]). Local-only syncStatus defaults to saved, syncError nullable. Media: id, kind=image|video|audio, mimeType, byteSize, durationMs?, width?, height?, status=reserved|uploading|processing|ready|failed. localPath is client-only. Backend never accepts filesystem paths.

POST /api/uploads {kind,byteSize,clientUploadId} -> {media}; PUT /api/uploads/:id/content streams bytes -> {media}; GET /api/uploads/:id -> {media,error?}; DELETE /api/uploads/:id cancels only unbound media. Media content GET/HEAD /api/media/:id/content and /thumbnail requires ownership, supports single Range. Source caps image=10MiB/video=50MiB/audio=2MiB. Processed total per record <=45MiB, per-account stored+reserved <=1GiB. <=5 images, <=1 video <=15000ms, <=1 audio <=60000ms. Node uses ffmpeg/ffprobe configured through FFMPEG_PATH/FFPROBE_PATH or PATH; startup must check real tooling. Tests may inject tools only for focused unit tests; real media tests also required.

POST /api/sync {branchId,baseRevision,commands:[{commandId,type,payload}]} -> {state,branchMode:active|records_only,receipts:[{commandId,entryId?,progressApplied}],entries:[saved entries]}. Types: claim {questId}, stop {}, draft {questId,text,mediaIds}, complete {clientRecordId,questId,text,mediaIds,createdAt}, next {}. Branch initial baseRevision is checked against canonical progress; server persists the branch's last applied revision. On any revision conflict the entire branch permanently becomes records_only: valid completed records still save, all draft/progress actions stop changing canonical state. Duplicate command IDs return persisted receipts; same ID/different content conflicts. Tombstones prevent deleted records being recreated by old complete commands. State transitions, media binding and receipts are transactional; media work never runs within a DB transaction.

POST /api/sync-status takes the identical original wire body and returns {state,branchMode,receipts,entries,missingCommandIds}. It is read-only: no command execution, branch creation, or date rollover. Existing command IDs require the original payload hash (otherwise 409); missing IDs are explicitly listed. If a branch does not exist, branchMode is active when baseRevision equals canonical progressRevision, otherwise records_only; this is advisory until actual sync. A complete receipt whose entry is absent means it has already been deleted and must not be recreated locally. The same 16KiB/10-command limits apply. Clients persist the exact wire payload before sending, query receipts after an uncertain response, and may replace expired upload IDs only for commands explicitly reported missing; already committed payloads are immutable.

POST /api/update-entry {id,text,mediaIds,expectedRevision,requestId} -> {entry,state}; POST /api/delete-entry {id,requestId} -> {state}. Only committed edits detach original attachments. Persistent cleanup queue survives account/record deletion. Unbound uploads expire after 24h; referenced drafts do not expire. Export endpoints are removed.

## Dart domain contract (root implements)

MediaKind enum image/video/audio. MediaAttachment has constructor required id,kind; optional mimeType='',byteSize=0,durationMs,width,height,status='ready',localPath; toJson/fromJson/copyWith. JournalEntry existing constructor stays compatible, adds attachments=[], revision=1, updatedAt?, syncStatus='saved', syncError?. AppSnapshot adds draftAttachments=[],progressRevision=0,recommendationHistory=[],entryCount? (default entries.length),conflictDrafts=[],nextCursor?; existing copyWith stays compatible. ConflictDraft {id,questId,text,attachments,createdAt}. EntryPageResult {entries,nextCursor,total}. SyncSummary {pending=0,uploading=0,failed=0,message?,requiresLogin=false}. recommendQuestId({required List<String> preferences, List<String> history=const [], String? currentId}) returns ID, deterministic matching then least recent then forward catalog order. appendRecommendation(history,id) caps at 40. localDay always Asia/Shanghai.

## Repository interface (repository agent implements)

Preserve existing methods except remove exportData. saveDraft(String text,{List<MediaAttachment>? attachments}); complete(String text,{List<MediaAttachment>? attachments}); logout({bool discardPending=false}). Add queryEntries({String query='',String? cursor}); updateEntry(String id,String text,List<MediaAttachment> attachments,int expectedRevision); stageMedia(String path,MediaKind kind,{int? durationMs}); syncNow({bool allowMetered=false}); getSyncSummary(); Stream<SyncSummary> get syncUpdates; mediaHeaders(); String mediaUrl(MediaAttachment media,{bool thumbnail=false}); resumeConflictDraft(String id); discardConflictDraft(String id); dispose(). Return snapshots for existing state mutations and updateEntry/resume/discard; EntryPageResult for queryEntries; MediaAttachment for stageMedia; Map<String,String> for async mediaHeaders; SyncSummary for async getSyncSummary; void futures for syncNow/dispose.

SQLite client is authoritative for pending work only, cloud for saved data. Persist source files before transactions. Snapshot/queue/record creation is atomic. 20 pending records/500MiB device quota. Background and foreground use one persistent task lease. WiFi automatic; allowMetered authorizes a captured batch only. No token/password inside SQL. On auth failure retain account identity and queue, mark requiresLogin. Other accounts cannot send/read it. Auth uses secure token store. UI fixture may be a separate in-memory fake under test/, not a production local-account fallback. Keep LocalQuestRepository only temporarily if needed while tests transition, then remove.

Media upload state changes must be persisted, preserve stable IDs across retries, poll processing to ready, never remove local source until record receipt. Recover gallery results against the original account/edit context. Record editing is online with revision checks; canceled editing cannot remove original bound media. Foreground auto sync and Android Workmanager share the same store and token handling.

## Catalog

Root supplies server/catalog.json (40 full records, preferenceTags) and server/catalog.mjs exports quests,nextQuest,questTitle,recommendQuest,appendRecommendation. Flutter uses the same catalog via generated const source. Old 16 IDs retained. Every preference >=8 tagged activities. No silent fallback for unknown quest IDs.

## Integration clarifications

- ConflictDraft additionally persists `branchId` and immutable `baseRevision`. `resumeConflictDraft(id)` returns an editor view without replacing canonical cloud progress. `saveConflictDraft(id,text,{attachments})` edits only that local draft. `completeConflictDraft(id,text,{attachments})` atomically queues a complete command on its original records-only branch, creates the pending record and removes the resolved draft. It never queues claim/next on a new active branch. The UI passes an explicit conflictDraftId to the editor; there is no global implicit editing context.
- `QuestRepository.cacheScope` is the normalized service identity; gallery-recovery markers include it as well as account and editor IDs.
- Outbox insertion uses a monotonic SQLite sequence, never UUID ordering within a millisecond. Captured sync batches fit the 16 KiB UTF-8 JSON limit as well as the ten-command limit.
- Root owns `sync_schedule.dart` and `sync_worker.dart`. Repository mutations may best-effort call `scheduleSyncWork()` from `sync_schedule.dart`. Android jobs are ordinary unmetered WorkManager tasks, with no expedited foreground service or notifications; repository connectivity still enforces WiFi and the shared SQLite lease.
- Only empty or protocol-v2 server databases may be opened. Existing v1 data is checked read-only and rejected without WAL/schema/data changes. Media directories are bound to their database identity; unknown files are never swept as orphans.
- `openDraftEditor(questId)` atomically captures `DraftEditorContext {snapshot,branchId,questId}`. Normal editors pass `expectedBranchId` and `expectedQuestId` to every save/complete; a background conflict cannot retarget an already-open editor to canonical cloud work. Mismatches preserve local text under the original branch's conflict draft, including when both devices have the same activity ID.
